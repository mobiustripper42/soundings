## Task 2: Phase 3.4 — run cycle (issue #43)

**Completed:**
- `firmware/src/core/runcycle.{h,cpp}` — `runOnce()` walks an array of `SensorSlot`, declares every slot whether or not it answered, faults the ones that didn't (DEC-002), reads battery into the header, serializes, transmits, sleeps `interval ± 30 s`. Node-type-agnostic, so parked issue #23 (Phase 2.5) is largely satisfied.
- Three seams that fall out of deep sleep being terminal: `iseqstore.h` (a counter in a member variable would ship `seq=0` forever, making issue #30's gap detector unbuildable), `irandom.h` (jitter must be asserted, not observed), `isampler.h` + `distance_sampler.h` (the cycle walks a set without knowing its types — the shape 3.5 fills from a manifest).
- `firmware/test/fakes/{fake_random,fake_seqstore,fake_sampler}.h`; `firmware/test/test_runcycle/` — 22 tests. Suite 32 → 54, all green; `pio run -e node` clean.
- `seq` advances even when transmit fails — a dropped packet consuming its number is what makes the loss visible; reusing it would close the gap issue #30 exists to find.

**Code review:** 2 findings, both fixed in `d6886bb`. (1) **Real bug** — `intervalMs - jitterMs` is unsigned, nothing enforced `jitter <= interval`, and a manifest with the two reversed produced a 4294963296 ms (49.7 day) sleep on a node whose sleep is terminal: dead until someone pulls the cell. Clamped rather than asserted — a node waking too often is recoverable over the air, one aborting on boot is a reflash in a tunnel. Three tests pin it. Invisible to the original 19 because both shipped constants happened to satisfy the invariant, and 3.5 was about to start filling both from config. (2) The Busy-retry loop's no-backoff assumption is now stated in the `IRadio::send()` contract, where issue #48's driver author will read it.
