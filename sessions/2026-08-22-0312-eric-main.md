**Test-design note worth keeping:** the frame-accounting tests run with the settle window
switched off, deliberately. `FakeByteSource` hands over a byte per poll, so against a

— the window would end mid-frame, one frame would be lost to resync, and each test's
expected median would silently depend on how many times the driver's loop read the clock.
The window gets its own test proving it by contrast instead.

## Task 2: Phase 3.9a — serial framing contract + SerialPacketSource

**Completed:**
- **`contracts/serial-framing-v1.md`** — a three-field envelope (`0xA5 0x5A`, u8 length,
  payload) for carrying packet-v1 over the gateway board's USB link, plus the five-step
  read algorithm and the three resync cases it must survive: board reset, reset
  mid-frame, and daemon restart landing mid-frame.
- **`firmware/src/core/serial_framing.{h,cpp}`** — the encoder, in `src/core` rather than
  the gateway sketch so `pio test -e native` compiles it. A framer in `src/esp32` would
  meet its decoder for the first time on a bench.
- **`gateway/soundings_gateway/framing.py`** — `SerialFramer`, the resync state machine.
  Emits *candidates*; the payload CRC settles what is real, on the path `decode()`
  already provides for radio-corrupted packets.
- **`SerialPacketSource`** behind the existing `IPacketSource`, taking anything with
  `.read(n)` via a structural `ByteStream` protocol — **no pyserial dependency added.**
  Two stream conventions documented on the class: `b""` means quiet (a read timeout, not
  EOF — ending iteration there would stop the daemon the first quiet minute), `EOFError`
  means done (so a test can script a finite stream with no test-only flag on the
  production class).
- **32 new tests** — 9 native, 23 pytest. Suites: 134 pytest, 101 native, node build
  clean at 7.9% flash, `npm run verify` green.

**Three design calls, with their reasons:** no frame checksum (the payload already
carries CRC-16/CCITT-FALSE and USB's link layer is CRC-protected; a second checksum is a
second thing to get wrong); no shared vector file, departing from packet-v1 deliberately
(one-way, fixed-shape, no round trip to pin, and a framing bug means *nothing* decodes on
the first bench try rather than a plausible wrong number for a season); encoder not
behind an adapter seam (a seam earns its keep where a real implementation and a fake both
exist — this is a pure function over bytes).

⚠ **Three false greens caught during development, before review.** All three C++
"refuses bad input" tests passed against a stub returning 0 unconditionally — *a stub
that refuses everything satisfies every refusal assertion.* Each now also asserts the
adjacent legal length succeeds, pinning the boundary rather than a general willingness to
say no. **Same class as the one caught in PR #72, which makes it a pattern rather than an
accident:** refusal tests are the ones that survive a null implementation, and they need
a positive case in the same test or they assert nothing.

**A test also found a property I had documented wrong**, before review saw it: a
truncated frame whose `LEN` byte was valid *absorbs* the bytes behind it rather than
simply failing to complete. Contract and test both corrected to describe what actually
happens.

**Code review:** 2 findings. **The real one is arithmetic I never did.** I wrote that the
absorption cost was "at most one following frame lost." The smallest complete frame is
3 + 14 = 17 bytes and the largest window is 46, so ⌊46 ÷ 17⌋ = **two** whole frames fit —
30 minutes of tank level at the 15-minute cadence, and precisely the number someone
staring at a gap in the chart would trust. The contract now states the bound in *bytes*
(what the code guarantees) and derives the frame count beside it, pinned by a test that
builds the worst case explicitly. The second finding asked whether a new wire contract
needs its own DEC; answered in the PR — framing and modem parameters are one subject per
the operator's call, and that DEC lands in 3.9b, which stacks directly on this branch.

## Task 3: Test audit — nineteen tests were green against a do-nothing implementation

**Why this task existed:** the same false green appeared in Tasks 1 and 2 — three of nine
C++ tests in 3.9a, one in 3.8a. Two in a row made it a pattern rather than an accident,
and the operator called for a sweep before 3.9b writes more tests in the same style.

**The finding, and it is the one worth remembering:**

> The clamp that stops a misconfigured node deep-sleeping for **49 days** was pinned by
> three tests that all asserted a sleep of **0** — arithmetically correct at the low end
> of the jitter window, and exactly what `nextSleepMs() { return 0; }` returns. With that
> body substituted, all three passed **and so did the entire `test_manifest` suite,
> 17 of 17.**

A sleep of 0 is also not a harmless value to have agreed on: it means the node never
sleeps, which is the wake-forever failure DEC-006 names as the real battery killer. The
one value those tests concurred on was the value that would have been a disaster.

**Method matters more than the count. Mutation, not grep.** Pattern-matching for
negative-shaped assertions found 24 candidates and **missed a whole class** —
`assert ms <= limit` is satisfied by `0`, and an upper bound does not look negative.
`test_jitter_larger_than_interval_stays_bounded_for_any_rng_value` survived exactly there.
Stubbing a function to its null return and seeing what still passes asks the question
directly instead of guessing at its shape.

**Completed:**
- **19 tests strengthened across 7 files** — `test_runcycle` (3), `test_manifest` (1),
  `test_native` (2), `test_packet` (1), `test_derive` (8, plus a shared
  `assert_derives_normally` control), `test_publish` (3), `test_framing` (1). Each refusal
  now carries the adjacent legal case in the same test; where the correct answer genuinely
  is a null value, the test takes a second draw whose answer isn't.
- **Every mutation re-run afterwards** to confirm the strengthened versions die:
  `nextSleepMs → 0` (4 now fail), `Elapsed::expired → false` (2), `serialize → 0` (1),
  `derive_tank → []` (9 → 1), `envelope → None` (4 → 1). Remaining survivors belong to
  other functions and are correct passes.
- **`.claude/CLAUDE-context.md` § Testing** carries the convention now, including the

- Suites: 101 native, 134 pytest, `npm run verify` green.

**⚠ The airtime table inverted the plan.** 3.9b was specced expecting `t_active > 2 s`
(`HARDWARE_BUILD_PLAN.md:812`) to be the constraint, so the job looked like buying airtime.
It isn't: the wake is dominated by MCU-on time and the spread between the fastest and
slowest usable setting is ~10 % of one wake. **There was nothing to buy with speed**, so
the budget went to margin instead. Worth remembering — the estimate assumed the opposite.

**⚠ The bench found a bug of a class no host test can catch.** RadioLib's receive timeout
is in **milliseconds**; I passed microseconds. The node sat in receive for 250 seconds
instead of 250 ms — booted, radio up, transmitted, then never reached deep sleep, which
from outside is indistinguishable from a crash. RadioLib's own debug line says
`"Timeout in %lu ms"`. **I guessed a third-party unit**, which the shell explicitly warns
against, and only a physical board could tell me.

Three things that could have gone wrong and didn't: TCXO at 1.6 V is right (the board's
most common bring-up trap), pins match the variant header, and the jitter clamp produces
real spread (19823, 19313, 21938 ms).

**Code review:** 3 findings, all fixed. **The headline is a repeat of my own reasoning
being applied backwards.** The gateway sketch hand-rolled the framing reader because it was
"only fifteen lines" — *exactly* the argument rejected for the **encoder** one task
